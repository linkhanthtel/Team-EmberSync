# EmberSync

**Reading the fire season of British Columbia from orbit, one move at a time.**

EmberSync turns 25 years of NASA FIRMS satellite fire detections (2001 to 2025) into a fire calendar for the six BC Wildfire Service fire centres. It harmonises two generations of sensors (MODIS and VIIRS) onto one calendar, keeps low-confidence detections in view on a watch list, and adds short, team-reviewed AI insights to help a fire manager decide what to prepare first.

Built by Team EmberSync for the NASA Space Apps Challenge 2026.

## The five moves

The app is organised around five moves. Each move is a screen, and each screen is backed by a data file in `src/data/`.

| Move | What it does in the app | Data behind it |
|---|---|---|
| **Scan** (done) | How we scanned the world's fire data and why the MODIS record matters now, as MODIS missions end and Suomi-NPP science data closed in November 2026. A short methods note. | FIRMS yearly Canada archive |
| **Spot** (done) | How we spotted British Columbia as a fire-prone territory and split it into its six fire centres. A short methods note. | `bc_fire_centres_simplified.geojson` |
| **Block** | The fire calendar: month against year, 2001 to 2025, with harmonised hotspot counts and fire energy for each fire centre. | `bc_monthly_calendar_2001_2025.csv` |
| **Watch** | A BC map filtered by fire centre. Click a calendar month to see that month's hotspots, with lone dots on the watch list. | `bc_month_cells_2001_2025.csv`, `bc_watch_list_2001_2025.csv` |
| **Make the call** | One-line insights for each fire centre and month, generated by Gemini and reviewed by the team, with an insights-only download. | Insights CSV (generated from the calendar) |

Scan and Spot appear greyed out with a done tick: they are the thinking already done to reach the calendar.

## Data

Source: [NASA FIRMS](https://firms.modaps.eosdis.nasa.gov/) yearly country archive for Canada, downloaded 14 Nov 2026.

- MODIS Collection 6.1 standard product, 2001 to 2025
- VIIRS Suomi-NPP 375 m standard product, 2012 to 2025

Cleaning, from 8,250,767 Canada detections to 1,792,662 BC vegetation-fire detections:

1. Kept vegetation fires only (FIRMS type 0). Dropped volcanic (type 1), other static land sources such as industrial heat (type 2) and offshore (type 3) detections.
2. Clipped to BC and tagged each point with its fire centre by a spatial join to the BC Wildfire Service fire-centre boundaries.
3. Kept low-confidence points and flagged them (`low_conf`: MODIS confidence under 30, VIIRS confidence "l").
4. Assigned each point to a 0.1 degree grid cell.

| File | Rows | What it holds |
|---|---|---|
| `bc_firms_clean_2001_2025.csv.gz` | 1,792,662 | Every cleaned BC detection (gzipped) |
| `bc_monthly_calendar_2001_2025.csv` | 1,800 | 6 fire centres x 300 months: counts, fire energy, low-confidence counts, harmonised values |
| `bc_month_cells_2001_2025.csv` | 81,647 | One row per 0.1 degree cell per month per sensor, for the map |
| `bc_watch_list_2001_2025.csv` | 45,015 | Lone dots: the only detection in its 0.1 degree cell on that day |
| `bc_fire_centres_simplified.geojson` | 6 | Fire-centre boundaries for the web map |

## Method

**From brightness to fire power.** Each FIRMS detection carries brightness temperatures from the sensor's middle and thermal infrared channels (`brightness` and `bright_t31` for MODIS, `bright_ti4` and `bright_ti5` for VIIRS). NASA uses these to detect fire pixels against their background (Giglio 2016; Schroeder 2014), then derives fire radiative power (FRP, in MW) with the middle-infrared radiance method (Wooster 2003). We keep the brightness columns in our raw archive for traceability and build all fire energy values from FRP.

**Fire energy.** FRP is summed per 0.1 degree cell per day, then rolled up per fire centre per month. We call this monthly sum "fire energy"; it is not a time-integrated FRE.

**One calendar from two sensors.** MODIS and VIIRS see fire differently (pixel size, overpass time, fire band). Following Li 2018 and Li 2020, we fitted two MODIS-to-VIIRS factors on the overlap years 2012 to 2025 (1,008 fire-centre months, least squares through the origin):

| Factor | Value | Fit (r) |
|---|---|---|
| Hotspot count | 4.92 | 0.985 |
| Fire energy | 0.52 | 0.988 |

The fire energy factor below 1 is in line with Li 2018, who found VIIRS FRP about 47% smaller than MODIS for large boreal fires.

The calendar shows MODIS x factor for 2001 to 2011 and VIIRS as observed from 2012. Low-confidence points enter the totals under the same rule for both sensors.

**Validation.** The factor is shown before and after harmonisation, and ten calendar cells are checked by hand against the FIRMS map.

## AI

Insights are batch-generated with Google Gemini from a prompt template written by the team. Each insight is one sentence of at most 25 words per fire centre and month, uses only numbers from the data, names the sensor and date range, and points to one watch-list area where it fits. If data is missing, the insight says "Insufficient data". Every insight is reviewed by the team before it appears in the app. There are no live AI calls in this build, and the API key is kept in a gitignored `.env` file.

## Run it

```bash
npm install
npm run dev            # http://localhost:5173
npm run build          # type-check + production build
npm run gen:summary    # rebuild src/data/derived/firms_summary.json from the raw .csv.gz
```

## Code map

```
src/data/                       Source data (see Data above); derived/firms_summary.json is generated
scripts/summarise-firms.ts      Streams the 1.79M raw detections into a small summary for Scan/Spot
src/lib/fire.ts                 Types, CSV parsing, lazy loaders, factor refit
src/lib/insights.ts             Make the call: reviewed insights CSV, or rule-based drafts
src/lib/theme.ts                Colours (fire-centre palette, sensor colours, fire ramps), number formats
src/components/BcMap.tsx        d3-geo BC map (Albers, zoom to centre, 0.1° cells, lone dots)
src/components/charts.tsx       Fire calendar, annual bars, sensor bars, factor scatter
src/screens/                    Scan, Spot, Block, Watch, Call: one file per move
```

The calendar and the FIRMS summary are bundled. The map cells, watch list and fire-centre boundaries are fetched the first time a screen needs them. The raw `.csv.gz` is only read by the summary script, never by the browser.

The fire-centre GeoJSON uses RFC 7946 ring order (counter-clockwise); `loadCentres()` reverses the rings for d3-geo.

Place names: GeoNames (geonames.org), CC BY 4.0

**Insights file.** Make the call reads any `src/data/*insights*.csv` with columns `fire_centre, ym, insight` (ym as `YYYY-MM`). Rows in that file are shown as team reviewed. Until it exists, the screen shows rule-based drafts, labelled as drafts.
